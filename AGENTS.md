# Repository Guidelines

## Project Overview

Wren-Odin provides Odin bindings for the [Wren](https://wren.io/) scripting language, enabling bidirectional embedding of Wren in Odin applications. The primary use case is game development scripting — game logic runs in Wren while performance-critical systems (rendering, physics, audio) stay in Odin.

The library exposes two API layers:
- **High-level API** (recommended): Odin functions receive `[]Value` args and return `Value` — no slot management, no raw pointers
- **Low-level API**: Direct slot-based operations wrapping Wren's C API — for advanced use cases

## Architecture & Data Flow

```
Wren VM (C)  ←→  wren_raw.odin (raw FFI)  ←→  trampolines.odin (C→Odin bridge)
                                                    ↓
                                            slots.odin / vm.odin (low-level public API)
                                                    ↓
                                      high_level.odin + value.odin (high-level public API)
                                                    ↓
                                            User code (Odin game logic)
```

**Foreign method call flow:**
1. Wren script calls a `foreign` method
2. Wren C API invokes `bind_foreign_method_trampoline` (registered in Configuration)
3. Trampoline looks up handler in `g_foreign_method_handlers` dispatch table by `module + class + signature`
4. For high-level API: wrapper function (wrapper_0..63) calls `call_handler` which converts slots → `[]Value`, invokes user handler, converts result back to slot 0
5. For low-level API: user's `proc "c" (vm: ^RawVM)` is called directly

**Key dispatch tables:**
- `g_foreign_method_handlers` — `[dynamic]ForeignMethodHandler` (module/class/signature/handler)
- `g_foreign_class_handlers` — `[dynamic]ForeignClassHandler`
- `g_high_level_handler_table` — `[64]HighLevelMethodFn` (fixed-size, indexed by wrapper ID)

### Source Files (`wren/`)

| File | Purpose |
|---|---|
| `wren_raw.odin` | Raw C FFI — 1:1 bindings to `wren.h`. Opaque `RawVM`/`RawHandle`, all `wren_*` C declarations. **Internal only.** |
| `types.odin` | Public types: `VM`, `Handle`, `Result`, `ValueType`, `ErrorType`, callback signatures (`WriteFn`, `ErrorFn`, etc.) |
| `config.odin` | `make_configuration()`, callback setters (`set_write_fn`, `set_error_fn`, etc.), heap size config |
| `vm.odin` | VM lifecycle: `new_vm`, `free_vm`, `interpret`, `call`, `collect_garbage`, handle management |
| `slots.odin` | Low-level slot API: `ensure_slots`, `get_slot_*`, `set_slot_*`, list/map iteration, `get_variable` |
| `trampolines.odin` | C→Odin bridge: global dispatch tables, trampoline functions for all Wren callbacks. **Internal.** |
| `value.odin` | `Value` tagged union (`bool`, `f64`, `string`, `[]Value`, `Map`, `rawptr`), type-safe extractors/constructors, `get_value`/`set_value` converters |
| `high_level.odin` | High-level API: `HighLevelMethodFn`, `register_method`, 64 fixed wrappers, `call_handler` dispatcher, `make_vm`/`call_method` helpers |
| `foreign_class.odin` | Placeholder for declarative struct-tag binding (future work) |

```bash
# Build Wren static library (must run first)
./build_wren.sh

# Build test runner
odin build test_runner -out:build/test_runner

odin build examples/runner.odin -file -out:build/runner && ./build/runner ecs

# Format check
odin fmt -check wren/
```

## Code Conventions & Common Patterns

### Naming
- **Types**: PascalCase (`VM`, `Handle`, `Value`, `Map`, `Result`)
- **Procs**: snake_case (`new_vm`, `register_method`, `get_slot_double`)
- **Constants**: SCREAMING_SNAKE_CASE (`MAX_HIGH_LEVEL_METHODS`)
- **Files**: snake_case (`high_level.odin`, `foreign_class.odin`)

### C FFI Boundary
- Raw C functions use `proc "c"` calling convention
- C strings (`cstring`) are converted to Odin `string` via `strings.clone_to_cstring` / manual copy + `defer free`
- Opaque C types (`^RawVM`, `^RawHandle`) are wrapped in Odin structs (`VM`, `Handle`)
- Slot indices use `c.int()` conversion at the FFI boundary

### Memory Management
- Odin `string` from Wren: use `strings.clone_to_cstring` for C side, `defer free(rawptr(...))` for cleanup
- Wren handles: always `release_handle` when done — they pin GC roots
- VM lifecycle: `new_vm` → use → `free_vm` (frees callbacks + raw VM)
- Slice literals in Odin are stack-allocated — use `make()` for slices that outlive the function scope

### Error Handling
- `Result` enum: `.Ok`, `.CompileError`, `.RuntimeError`
- `ErrorFn` callback receives `ErrorType` (`.Compile`, `.Runtime`, `.StackTrace`)
- Type-safe extractors (`as_bool`, `as_num`, etc.) **panic** on type mismatch
- `set_value` panics on unsupported types (e.g., `rawptr` foreign objects)

### High-Level API Pattern
```odin
// Define handler
my_handler :: proc(args: []wren.Value) -> wren.Value {
    n := wren.as_num(args[0])
    return wren.num_value(n * 2)
}

// Register (module, class, signature, handler)
wren.register_method(vm, "./mymodule", "Math", "static Math.double(_)", my_handler)
```

### Wren Foreign Declaration
```wren
// In Wren script — must match registration signature exactly
class Math {
    foreign static double(n)
}
```

Signature format: `"static ClassName.method(_)"` for static, `"ClassName.method(_)"` for instance. Constructor: `"ClassName.init new(_)"`.

## Runtime & Tooling

- **Odin version**: `dev-2026-07` (pinned in CI)
- **Wren version**: git submodule at `vendor/wren/` (commit `4a18fc4`)
- **Build**: Wren is amalgamated to a single `.c` file, compiled with `cc -c -O2 -fPIC`, archived to `lib/libwren.a`
- **Platform**: CI runs on `ubuntu-latest`. Local development on macOS (ARM64). Known ARM64 stack alignment issue causes segfault during test runner cleanup (exit code 139) — tolerated in CI.
- **Dependencies**: Python 3 (for Wren amalgamation), `cc`/`ar` (for static library)

## Testing & QA

### Test Layers

| Layer | Location | What it tests |
|---|---|---|
| Wren language tests | `vendor/wren/test/` | 830 active tests across core, language, API, limit, regression categories |
| API tests | `test_runner/main.odin` | Custom Odin-side tests for handles, user data, error handling, lists, maps, foreign classes |
| Integration tests | `integration_tests/` | `simple_test` (low-level), `high_level_test` (high-level), `examples_test` (9 game-dev examples), plus focused tests for strings, bools, lists/maps, foreign classes, complex data |

### Known Issues Tolerated in CI
- **`literals.wren`**: Wren VM bug — crashes on raw strings with certain Unicode patterns ([Wren #1217](https://github.com/wren-lang/wren/issues/1217)). Filtered from failure detection.
- **Test runner exit code 139**: Segfault during cleanup (stack alignment issue). Tolerated only when zero test failures are detected in output.
